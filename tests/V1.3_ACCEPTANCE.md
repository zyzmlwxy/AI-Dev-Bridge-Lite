# V1.3 Acceptance — real report evidence preflight

> This acceptance checks **report metadata and Git lineage**, not the truth of the reported test results and not automatic execution of an AI agent.

## ChatGPT preflight

1. Confirm `.github/workflows/ai-dev-bridge-evidence.yml` uses `pull_request` and only `contents: read`, `pull-requests: read`.
2. Confirm it skips draft/fork PRs and never executes report-supplied commands.
3. Confirm `tests/test_bridge_evidence.py` checks malformed SHA, missing fields, failed test statuses, report-only Git ancestry, and stale code changes.
4. Confirm standalone `AGENTS.md` manual flow and V1.2 notifier remain independent and functional.

## WorkBuddy independent execution

Fetch the PR's latest **full 40-char HEAD SHA** at execution time and run the following checks separately; record actual exit codes:

```sh
git rev-parse HEAD
python3 -m py_compile .github/scripts/bridge_evidence.py
python3 -m unittest discover -s tests -p 'test_bridge_evidence.py' -v
python3 -m unittest discover -s tests -p 'test_bridge_notify.py' -v
```

Do not install Python or modify source without permission. Build: N/A (Python syntax validation), Deployment: NOT ATTEMPTED. If Python 3 is unavailable, record BLOCKED and the concrete reason.

After the checks, create one sanitized immutable report `.ai-collab/reports/PR-<PRnumber>-<tested7>-a1.md` on **the same PR branch**, without editing script, protocol or tests. Report must preserve:

```text
[WORKBUDDY_EXECUTION_REPORT]
Protocol: 1.3
Repository: zyzmlwxy/AI-Dev-Bridge-Lite
PR: <actual PR URL>
Attempt: 1
Tested Commit SHA: <actual full 40-char SHA>
Environment: <actual OS/Python/Git versions>
Build: N/A
Tests: PASS / FAIL / BLOCKED
Test command: <actual test command>
Test exit code: <actual integer or NOT RUN>
Failure category: NONE / TEST / CODE / ENVIRONMENT / PERMISSION / UNKNOWN
Overall: PASS / FAIL / BLOCKED
Deployment: NOT ATTEMPTED
Evidence: <real exit codes and checks, sanitized>
```

Test command should name the actual unit-test command and Test exit code must match it; record each additional check and its exit in Evidence. Never mark PASS for unrun steps. Do not merge main or deploy.

## Expected GitHub Actions behavior

**Before a report exists**: V1.3 evidence workflow runs with `WAITING_FOR_REPORT` (not Tests PASS), offline tests should be green. If the workflow was not triggered, record NOT RUN.

**After report-only push**: V1.2 notifier should post `REVIEW_PENDING` and V1.3 evidence workflow should produce `EVIDENCE_READY`, with a link to the added report and a full tested SHA. The evidence checker must compare the tested SHA with the report commit HEAD and fail if the range changes source/config/test files.

**Negative-path checks**: Offline unit tests cover forged full SHA, invalid attempts, conflicting PASS/FAIL exits, duplicate attempt reports, code changes after testing and non-ancestor comparisons. A live destructive negative test is *not* required; do not intentionally break the PR branch or erase reports just to see failures.

## ChatGPT review

1. Discover report path from PR changed-file list; do not ask the user to paste it.
2. Compare the report's real tested SHA to its later upload commit SHA; verify only report file(s) were added.
3. Read GitHub Actions job summary and logs: green `WAITING_FOR_REPORT` only means the preflight job ran; `EVIDENCE_READY` does not mean real test PASS.
4. Verify WorkBuddy actual commands and exit codes against the unmodified tested SHA; later report-only commits do not invalidate the test.
5. Archive exact test SHA, report SHA, run URLs, outcomes and any blockers. Keep PR open until user explicitly approves release.

## Release gate

No merge or V1.3 tag without actual WorkBuddy report, GitHub Actions evidence check and independent ChatGPT review. No automatic agent wakeup, no production deployment.

# V1.1 acceptance drill: failed check → fix → retest

> This is a deliberately controlled, non-destructive **protocol regression exercise** for the ChatGPT–WorkBuddy handoff. It is not a product build, deployment, or a claim that a real customer bug has been reproduced.

## Preparation

Use the open V1.1 PR's **latest** head, not a SHA copied from an older conversation. Follow `[AI_DEV_BRIDGE_HANDOFF]` in the PR description and the root `AGENTS.md`.

The sample fixture is `tests/fixtures/v1.1-task-state.txt`. **Attempt 1 intentionally contains `PENDING` rather than `READY`.** A real command should therefore fail. The fixture must not be modified by WorkBuddy.

## WorkBuddy — Attempt 1 (expected FAIL)

On the PR's tested checkout, run these Git commands, capturing exact exit codes:

```sh
git rev-parse HEAD
git grep -q '## 7. V1.1' -- AGENTS.md
git grep -q '^READY$' -- tests/fixtures/v1.1-task-state.txt
```

- The protocol check should return exit code `0` if V1.1 text is present.
- The fixture check should return exit code `1` while the file contains `PENDING`. **Record its actual exit code**, do not simply quote this expectation.
- `Build: N/A` because the release has no compiled application.
- `Tests: FAIL` if the checked fixture does not match `READY`, `Failure category: TEST`, `Overall: FAIL`. A failure in this specific drill is **expected**, but it is still a real failing attempt and must not be marked PASS.
- Leave a PR comment or create the versioned Git SSH report under `.ai-collab/reports/PR-<PR>-<tested7>-a1.md`. Do not alter the fixture or main. Reports must not include secrets or absolute private paths.

## ChatGPT — inspect and fix

When the user says **"验收此 PR: <PR URL>"**, ChatGPT should locate the report itself from the PR's changed files/comments and:

1. Verify the actual tested SHA and report commit diff.
2. Set status `FIX_REQUIRED` for the failing attempt; do not merge.
3. Change exactly `tests/fixtures/v1.1-task-state.txt` from `PENDING` to `READY` on the existing PR branch.
4. Re-read the PR head. Send only the PR URL back to the user to relay, requesting Attempt 2.

## WorkBuddy — Attempt 2 (expected PASS)

Check out the latest PR head and actually re-run the same commands. If both checks exit `0`, report `Tests: PASS` and `Overall: PASS` with `Attempt: 2`, the **new tested full SHA**, and the actual commands / exit codes. Preserve the previous a1 report. Submit a new a2 report file or comment.

## ChatGPT — final review

- Find both attempts, verify two separate tested SHAs and both report commits, using GitHub's compare and changed file information.
- A report-only commit does not force a retest; source/fixture changes do.
- Confirm the source fix was limited to the deliberate fixture (plus report/metadata changes).
- Mark `VERIFIED` only if Attempt 2 passed with actual evidence. The user still decides whether to merge and publish.
- If the failure was environment or permission-related instead, mark `BLOCKED` and report the reason; do not pretend the drill passed.

## Important boundaries

This drill tests the **failure-classification and retry-handoff protocol**, not autonomous repetition. User interaction is still required between WorkBuddy and ChatGPT. Do not install software, push to main, delete branches, merge or deploy.

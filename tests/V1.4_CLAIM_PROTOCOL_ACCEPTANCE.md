# V1.4 Claim Protocol — Acceptance Matrix

Status: **design/test plan only**. No project code is executed by these cases.

This matrix is paired with `.ai-collab/V1.4_CLAIM_PROTOCOL.md`. Run implementation tests only on a disposable repository or explicitly authorized test PR. Capture exact Git commands, exit codes, source SHA, candidate SHA, remote ref SHA and sanitized output.

## A. Discovery and preflight

| ID | Setup | Action | Expected result | Must not happen |
|---|---|---|---|---|
| PRE-01 | No open PR with opt-in label | Poll allowlisted repo | `NO_TASK` | No Git write |
| PRE-02 | Open, non-draft, same-repo PR; allowed base; label present | Read twice | Same PR and full HEAD SHA; `TASK_FOUND` | No claim until all checks pass |
| PRE-03 | Draft PR | Poll | `BLOCKED` or ignored per documented queue policy | No claim ref |
| PRE-04 | Fork PR | Poll | `BLOCKED` | No fork code execution |
| PRE-05 | Missing opt-in label | Poll | Not eligible | No claim ref |
| PRE-06 | Disallowed repository/base | Poll | `BLOCKED` | No write |
| PRE-07 | HEAD changes between first read and pre-claim re-read | Continue preflight | `STALE` | No claim |
| PRE-08 | Required project config is missing/unknown | Poll execution candidate | `BLOCKED` for execution | No guessing of commands |

## B. Claim creation and duplicate handling

| ID | Setup | Action | Expected result | Must not happen |
|---|---|---|---|---|
| CLM-01 | Deterministic claim ref absent | Create candidate from exact PR HEAD and push | One claim ref; one initial claim commit; parent equals PR HEAD | No extra commits or unrelated files |
| CLM-02 | Claim ref exists with matching valid run key/HEAD | Poll same PR/SHA | `DUPLICATE_SKIP` | No second initial claim commit |
| CLM-03 | Claim ref exists but record is missing/malformed | Poll | `BLOCKED` | No overwrite or repair in place |
| CLM-04 | Claim ref record has different repository/PR/SHA | Poll | `BLOCKED` | No execution |
| CLM-05 | Push returns an error but remote ref matches this attempt ID and valid record | Re-read remote | Claim confirmed after verification | No blind second push |
| CLM-06 | Push outcome unknown and remote reads remain inconclusive | Reconcile read-only | `UNKNOWN`; wait/manual reconciliation | No execution or forced retry |
| CLM-07 | Claim push gets non-fast-forward rejection; remote winner is valid for same run key | Re-read winner | `DUPLICATE_SKIP` | No force push |
| CLM-08 | Claim push gets non-fast-forward rejection; remote record is invalid or for another task | Re-read winner | `BLOCKED` | No automatic cleanup |
| CLM-09 | Local branch has stale/extra commits before initial claim | Validate parent/diff | Reject local candidate | No push |
| CLM-10 | Claim record exists | Poll repeatedly | Claim JSON and timestamp stay unchanged | No timestamp-only claim commits |

## C. Recovery and ambiguous outcomes (MVP scope)

| ID | Setup | Action | Expected result | Evidence required |
|---|---|---|---|---|
| CON-03 | Single executor loses connection during push | Reconnect and inspect | Remote truth determines `CLAIMED`, `DUPLICATE_SKIP`, or `UNKNOWN` | No duplicate write before read-back |
| REC-01 | PR HEAD changes after claim but before execution | Re-read PR | Old run becomes `STALE`; no execution of new SHA under old claim | Old claim preserved |
| REC-02 | Worker crashes after claim, before execution | Re-poll | Existing claim prevents a second automatic claim; `RECOVERY_REQUIRED` or manual review | No claim stealing |
| REC-03 | Worker crashes during command / result uncertain | Reconcile | `RECOVERY_REQUIRED`; human decides whether retry is safe | No automatic rerun |
| REC-04 | Claim ref protected or SSH write permission absent | Attempt within approved test | `BLOCKED` with actual error | No alternate credential or permission bypass |
| REC-05 | Claim record has unknown schema version | Poll | `BLOCKED` | No destructive migration |

## D. Deferred multi-executor concurrency tests (not an MVP blocker)

The initial deployment profile assumes one active WorkBuddy executor per queue. The following cases are **explicitly deferred** and must not block acceptance of the single-executor MVP. They become required acceptance tests before a future deployment enables multiple independent WorkBuddy executors. Keep the task key, claim-ref format, record schema and state machine executor-neutral so this extension remains possible.

| ID | Setup | Action | Expected result | Evidence required |
|---|---|---|---|---|
| CON-01 | Two independent executors, same PR HEAD, deterministic ref absent | Synchronize them to push distinct candidate commits concurrently | Exactly one valid candidate wins; the other validates the winner and returns `DUPLICATE_SKIP` | Both command results, winning ref SHA, valid record, no force push |
| CON-02 | Two executors race for the same ref and one candidate has the wrong SHA | Race writes | Any mismatched contender returns `BLOCKED`; no execution proceeds under an invalid claim | Remote record and both outcomes |

## E. State-transition and report validation

| ID | Setup | Action | Expected result | Must not happen |
|---|---|---|---|---|
| ST-01 | Valid claim confirmed by this attempt | Execution feature still disabled | Remain `CLAIMED`; no command starts | No implicit execution authorization |
| ST-02 | Execution later explicitly enabled and command allowlisted | Start command on exact claimed SHA | `RUNNING` only after rechecking PR and SHA | No arbitrary PR-supplied command |
| ST-03 | Command fails | Produce report | `FAILED`, real exit code and sanitized evidence | No false PASS |
| ST-04 | Tests pass, report committed separately | Evidence gate checks tested SHA vs report SHA | `COMPLETED` only when evidence gate passes | No inheriting evidence after source/test/config changes |
| ST-05 | Report changes source/test/config after tested SHA | Evidence preflight | `EVIDENCE_INVALID`; rerun needed | No VERIFIED state |
| ST-06 | Any merge/release/deploy request | Executor receives task | Requires separate explicit human approval | No implicit promotion from tests passing |

## F. Stage 4 exit criteria

The protocol is not ready for unattended execution until all are true:

- [ ] Protocol document reviewed and accepted.
- [ ] PRE-01 through PRE-10 behavior is implemented or explicitly marked not applicable with rationale.
- [ ] CLM-01 through CLM-10 pass on disposable fixtures.
- [ ] Single-executor MVP topology is configured and overlapping scheduled runs within the same executor are serialized.
- [ ] Multi-executor race tests CON-01/CON-02 are marked deferred; they become mandatory only before enabling multi-executor mode.
- [ ] REC-01 through REC-05 pass.
- [ ] State transitions are append-only and the initial claim record is never rewritten.
- [ ] A single-flight guard prevents overlapping scheduled runs in the MVP.
- [ ] An explicit per-repository command allowlist exists; no arbitrary PR content becomes executable input.
- [ ] V1.3 evidence gate accepts a report-only commit and rejects stale/mixed evidence.
- [ ] User separately authorizes a harmless command-execution pilot.

Until exit criteria pass, the poller may discover tasks and perform authorized claim-protocol tests only. It must not run project commands, edit source, merge, release, or deploy.
